# chronicle memory format

This is the contract. `scripts/chronicle.py` implements it, but every rule here can be followed
by hand: the store is plain Markdown in git.

## Layout

```
docs/memory/
  MEMORY.md            generated index (committed)
  <slug>.md            one memory per file
```

Nothing else belongs in `docs/memory/`. Plans, runbooks, reviews and status reports live
elsewhere in `docs/`; a memory may point at them.

## Memory file

```
---
name: <slug>                 # == filename stem, ^[a-z0-9][a-z0-9-]{2,63}$
description: <one line, <=100 chars, specific; drives recall relevance>
type: <status|decision|contract|gotcha|env|reference>
updated: YYYY-MM-DD
---
<The fact first, 1-6 lines.>

**Why:** <reason, incident, or evidence>
**How to apply:** <what to do / avoid>

Related: [[other-slug]]   (optional)
```

The `# ...` annotations above are documentation; do not copy them into files.

Frontmatter rules:
- Flat `key: value` lines only. The value is everything after the first `:` (colons inside the
  value are fine), trimmed. Optional matching `"..."` or `'...'` quotes are removed; inside
  double quotes `\"` and `\\` are escapes, inside single quotes `''` is a quote.
- Quote a description that contains `: ` or ` #`, or starts with a YAML symbol, so YAML tools
  (GitHub's renderer) read it the same way. `chronicle new` always writes the description
  single-quoted (`'...'`, a `'` inside doubled), so YAML never reads it as null, a boolean, a
  number or a date; lint warns on unquoted values that YAML would reject or truncate.
- Keep `<!--` and `-->` out of descriptions: in the rendered index they would hide entries.
- All four keys are required. `name` equals the filename stem.
- `updated` is the date the fact was last confirmed or changed. Bump it when you edit the fact.

Body rules:
- The fact first, in 1-6 lines. Then `**Why:**` and `**How to apply:**`.
- One fact per file. Two facts that change for different reasons are two files.
- Optional last line `Related: [[slug]]` links other entries; lint warns on broken links.
- No `Last Updated:` lines, no session narration, no secrets, no personal data.

## Types

| Type | Holds | Section |
|---|---|---|
| `status` | Current state and next steps of in-flight work. Name must start with `status-` (e.g. `status-feat-billing`). Delete when the work merges. | Status |
| `decision` | A choice and its rationale. | Decisions |
| `contract` | An API, schema or integration invariant. | Contracts |
| `gotcha` | A failure mode: symptom -> cause -> guard. | Gotchas |
| `env` | An environment or tooling quirk. | Environment |
| `reference` | A pointer to an external resource: dashboard, doc, runbook location. | References |

## Index (MEMORY.md)

Generated and deterministic: the same memory files always produce the same bytes. The header
below is exact; it repeats the file format so the store can be edited without the tool.

```
# Project memory

<!-- Generated by chronicle from docs/memory/*.md frontmatter; edit memory files, not this list.
Memory file format (docs/memory/<slug>.md, one fact per file):
  ---
  name: <slug, same as the filename stem>
  description: <one specific line, at most 100 chars>
  type: status | decision | contract | gotcha | env | reference
  updated: YYYY-MM-DD
  ---
  <the fact first, 1-6 lines>
  **Why:** <reason, incident, or evidence>
  **How to apply:** <what to do or avoid>
To add a memory without the tool: create docs/memory/<slug>.md with the frontmatter above, then add its line below in the right section (sorted by name).
Spec: https://github.com/jnopareboateng/chronicle -->

## Status
- [status-feat-billing](status-feat-billing.md) — Billing branch: Stripe webhooks live in staging, invoice PDFs and proration next

## Decisions
- [auth-session-cookies](auth-session-cookies.md) — Browser auth uses HttpOnly session cookies backed by the sessions table, not JWTs
```

- Section order is exactly Status, Decisions, Contracts, Gotchas, Environment, References.
  Empty sections are omitted.
- Entries are sorted by name within a section.
- Entry line: `- [name](name.md) — description` (an em dash, U+2014).
- Files that fail to parse or have an invalid type are left out (lint reports them).
- `chronicle context` prints the index without the generated header comment, for SessionStart
  injection, capped at 9000 bytes by default (Claude Code shows hook output over 10,000
  characters only as a file and a 2,000-character preview; the installed Codex hook sets
  `additionalContextLimit` to 4000 tokens). The cap is never below 500 bytes.
- Past the cap no entry is dropped silently. Full lines come first, in index order; from the
  first line that would not leave room for the rest, each remaining section is one
  `## <Section> (names only; open docs/memory/<name>.md):` line followed by its entry names,
  comma-separated and wrapped. Only when even the names overflow does the output end with
  `... N more in docs/memory/MEMORY.md`.
- `context` reads at most 2,000,000 bytes of `MEMORY.md`. A larger index gets a line saying the
  entries past that point are not shown, and lint reports it as an error.
- `context` strips only the generated header comment (the leading comment starting
  `<!-- Generated by chronicle`, closed before any entry line); other comments stay.

## Merge story

- Memory files are separate paths, so parallel branches rarely conflict.
- MEMORY.md lines are independent and sorted, so `chronicle init` adds
  `docs/memory/MEMORY.md merge=union` to `.gitattributes`: git keeps both sides' lines instead
  of writing conflict markers.
- After any merge or rebase, `chronicle index` re-normalizes the index; `chronicle lint` flags
  drift and duplicate lines left by the union merge.
- A real conflict inside one memory file means two people changed the same fact: resolve it
  like code, against the current code.

## Budgets

| Item | Warn | Error |
|---|---|---|
| Memory file | > 2000 bytes | > 4000 bytes |
| Description | > 100 chars | |
| Index | > 80 entries or MEMORY.md > 9000 bytes (curate) | |
| Status entry | `updated` older than 21 days | |

## Lint classes

Errors (exit 1): missing or bad frontmatter, missing field, invalid name or filename, name not
equal to filename, invalid type, `status` entry not named `status-*`, bad date, file over 4000
bytes, invalid UTF-8, unfilled `chronicle new` template, MEMORY.md missing, over 2,000,000
bytes or not equal to the generated index, duplicate index lines, git conflict markers (`<<<<<<<` / `>>>>>>>` lines),
`Last Updated:` lines, secret patterns (`sk-...`, `ghp_...`, `github_pat_...`, `AKIA...`, Slack
tokens, private key blocks).

Warnings (exit 1 with `--strict`): file over 2000 bytes, description over 100 chars, `<!--` or
`-->` in a description, unquoted frontmatter value that YAML rejects or truncates, stale
status entry, index over budget, legacy memory files present, non-memory files in
`docs/memory` (dotfiles such as `.gitkeep` are ignored), duplicate descriptions, empty body,
broken `[[links]]`, email- or phone-like strings, process-narration terms (`Claude`, `Codex`,
`Opus`, `Sonnet`, `Haiku`, `GPT-n`, `subagent`, `this session`).

Output: one finding per line, `LEVEL path: message`. Messages never repeat a frontmatter value
(an invalid one is reported by field and length), so a pasted credential is not echoed.
A `docs/memory/` that exists but cannot be listed is a failure (exit 2), never an empty store.

## Good examples

`docs/memory/auth-session-cookies.md`
```
---
name: auth-session-cookies
description: Browser auth uses HttpOnly session cookies backed by the sessions table, not JWTs
type: decision
updated: 2026-09-14
---
Browser clients authenticate with an opaque session id in an `HttpOnly; Secure; SameSite=Lax`
cookie, looked up in the `sessions` table. JWTs are only for service-to-service calls.

**Why:** Role changes must revoke access immediately (security review, 2026-09); JWT expiry
windows could not guarantee that.
**How to apply:** New browser endpoints read `request.session`; never issue JWTs to browsers.

Related: [[contract-sessions-table]]
```

`docs/memory/alembic-enum-autogen.md`
```
---
name: alembic-enum-autogen
description: Alembic autogenerate ignores new Postgres enum values; write ALTER TYPE by hand
type: gotcha
updated: 2026-08-30
---
`alembic revision --autogenerate` does not detect values added to a Postgres `ENUM`.

**Why:** Symptom: deploy failed with `invalid input value for enum order_status`. Cause:
autogenerate diffs tables, not enum members. Guard: hand-written migration step.
**How to apply:** Any enum change gets `op.execute("ALTER TYPE ... ADD VALUE ...")`; check
autogenerated migrations for missing enum diffs before merging.
```

`docs/memory/status-feat-billing.md`
```
---
name: status-feat-billing
description: "Billing branch: Stripe webhooks live in staging, invoice PDFs and proration next"
type: status
updated: 2026-10-02
---
`feat/billing`: webhook handler and idempotency keys are merged to staging. Next: invoice PDF
rendering, then proration for mid-cycle plan changes.

**Why:** Multi-week work across several people; this is the hand-off point.
**How to apply:** Pick up from the next item; delete this entry when `feat/billing` merges.
```

## Bad examples

A session diary (narration, model names, test counts, several facts, a stamp):
```
---
name: session-notes-oct-6
description: What we did today
type: status
updated: 2026-10-06
---
Last Updated: Monday, 06-10-2026, 3:15 pm
Claude and a subagent refactored billing this session. 142 tests pass. Also fixed the login
bug and bumped three dependencies.
```
Fix: drop it. Record only a durable fact the work revealed (e.g. a gotcha), as its own entry.

A restatement of the code with a vague description:
```
---
name: api-endpoints
description: API notes
type: contract
updated: 2026-10-06
---
The API has GET /users, POST /users, GET /orders, POST /orders, DELETE /orders/{id} ...
```
Fix: delete it; the router is the source of truth. Keep only invariants the code cannot show
("order ids are ULIDs; clients sort by them").

A secret and personal data:
```
---
name: staging-access
description: How to reach staging
type: env
updated: 2026-10-06
---
Use key sk-EXAMPLEnotARealKey000000 and ask jane.doe@example.org (+1 555 123 4567) for VPN.
```
Fix: never store credentials or contacts. Point at where access is managed:
`reference` entry "Staging access is granted via the platform team's access-request runbook".
